## Independent payment and producer review

- Billing order creation/checkpoint and payment confirmation/outbox intent are coupled to their database effects. Confirmation uses a conditional PENDING transition before granting benefits and holds the invoice-series allocation lock. The actual database race test verifies a single credit grant and retained notification intent while Redis is unavailable.
- Checkout resumes an existing open session, does not start another when a completed session awaits confirmation, preserves exact provider parameters across uncertain retries, and verifies payment amount/currency/company at webhook confirmation. Cancellation/replacement uses request-state rechecks under the order lock.
- Review found that manual confirmation could leave a Stripe checkout payable. The payment owner added provider expiration/verification plus an under-lock recheck of the session and unresolved attempt before manual confirmation. Focused tests cover expiration failure and an attempt changed during provider I/O; the owner reports 37 payment/real-database tests passing after this fix.
- Company submission, approval/rejection and unsuspension now write their event intent inside the transaction. Trial granting remains in that transaction; unsuspension uses a conditional state transition. Approval/rejection still represent separate admin commands: repeating one can produce another historical notification, rather than claiming command-level exactly-once delivery.
- Claim withdrawal/refund/penalty, unassigned cancellation, SLA breach, delivery completion and dispute decisions now persist intents with the state change. Claim-slot mutations use the request lock and Serializable transaction timeout. Concurrent dispute decisions cannot delete a review or publish a second outcome.
- Runtime domain event producers route through the outbox, then `EventBusService`; only `request.status_changed` may broadcast without recipients. Private events with no targets do not become broadcasts. Existing session-expiry signals are intentionally not domain outbox events.
- Recovery retries retained failed timer jobs. Quote reconciliation paginates past renewed offers rather than allowing an old-version first page to starve later expired offers; pending withdrawal reminders also paginate. Tests cover that pagination and retained-failed-job retry.

## Residuals and rollout notes

### 2026-09-16 visual/resilience follow-up boundary

Security-close review of this follow-up: endpoint guards, critical-action idempotency/audit, ownership, SAFE uploads, error envelopes and cookies/CORS are unchanged (no new endpoint or server mutation). PASS for the touched boundary: saved-data storage failures block overwrite; no auth data is added to localStorage; visual test fixtures are guest-only and isolated; shader/environment assets are local/generated with no third-party asset request. Runtime packaging excludes source/local environment files and preserves the prior non-root runtime; its final container verification is still pending. Docker's external storage-move failure was diagnosed read-only; no reset, unregister, global restart or data deletion was performed.

1. Existing audit rows and previously emitted logs were not rewritten. Audit storage is append-only. Historical private data, signed links or auth cookies may already exist in historical logs; retention/access review and any remediation require an explicit operational decision. New redaction is not retroactive.
   - Update 2026-09-29 (E-admin-platform-8): new logs no longer contain client addresses, emails or raw error text (geo, business calendar, message crypto and quotes now log `safeErrorSummary`; an ESLint `no-restricted-syntax` rule blocks raw errors, `.message`, `.stack` and `String(e)` in logger calls; unexpected 500s log only kind/route pattern/top app frame/traceId). Successful health probes are no longer access-logged. Production logs live only in Railway; retention = the Railway plan's log retention (Hobby: 7 days, to be confirmed in the Railway UI), access = Railway project members. Restricting project membership and remediating historical logs remain PO operational decisions (pending).
2. Audit writes are awaited after successful HTTP handling, but are not transactionally coupled to every business commit. A hard crash between domain commit and audit write can leave an audit gap. Durable notification intents do not constitute a complete replacement audit ledger. Replaying a successful idempotent request may create another safe audit record.
3. Malware scanning remains the intentional mock. Metadata validation and immutable sealing do not provide antivirus protection. A crash after sealing but before linking can leave a private orphan copy. There is no broad bucket cleanup; any future cleanup must prove object non-reference first. The old PUT may recreate an unreferenced source until its signature expires, but cannot mutate the linked SAFE copy.
4. Notification delivery is at least once. Database uniqueness prevents duplicate in-app notifications per event/user. A crash after SMTP acceptance but before the delivery marker can resend email; exactly-once SMTP is not claimed. Historical lost events are not reconstructed by the new outbox.
5. Frontend mutation keys are scoped to the user and live hook instance, not durable across reloads. Do not advise a new key for an uncertain purchase. Old template-route receipts fail closed when their concrete target cannot be established. Unknown Stripe attempts beyond the safe retry window need reconciliation; do not delete their checkpoints to force another payment.
6. Existing access JWTs without `sid` fail the new active-family check. A valid refresh cookie can rotate and issue a new compatible JWT; otherwise the user must sign in again. Deploy REST, socket and frontend refresh changes together. Keep the intentional 30-second refresh grace period. Test an old browser session and a new login before rollout.
7. Apply additive outbox/completion/checkout migrations before the matching application and regenerate Prisma. Rollback must preserve pending intents and checkout attempts; do not drop unresolved work. Start Redis/storage/worker dependencies, verify outbox completion and PENDING_SCAN recovery, then confirm that audit and HTTP logs contain no credentials.
8. The remaining moderate Nest SSE advisory is tracked in [verification.md](verification.md); no SSE route was found and this app uses Socket.IO. This review is not a container vulnerability audit or substitute for final real-device UX/performance checks.
